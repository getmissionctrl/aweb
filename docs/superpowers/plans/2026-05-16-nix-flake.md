# Nix Flake Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Nix flake providing packages for all subprojects, a dev shell, a NixOS module for the server, an `.envrc`, and a process-compose based dev environment.

**Architecture:** Root `flake.nix` orchestrates four subproject packages (Go CLI, two Python services, TypeScript channel). A numtide/devshell provides all development tooling. A NixOS module under `nix/modules/` exposes declarative deployment of aweb+awid. `dev/process-compose.yaml` wires up postgres, redis, awid, and aweb for local development.

**Tech Stack:** Nix flakes, numtide/devshell, buildGoModule, buildPythonApplication (hatchling), buildNpmPackage, process-compose, NixOS modules

---

## Success Criteria

1. `nix build .#aw` — produces a working `aw` binary (Go CLI)
2. `nix build .#aweb` — produces the aweb Python package
3. `nix build .#awid` — produces the awid Python package
4. `nix build .#channel` — produces the channel npm package
5. `nix develop` — drops into a shell with go, python3, uv, node, npm, psql, redis-server, process-compose all on PATH
6. `nix flake check` — passes, including NixOS module evaluation tests
7. `devrun` command starts postgres, redis, awid, aweb via process-compose
8. NixOS module test verifies that aweb and awid systemd services start and respond on their health endpoints

---

## File Structure

```
flake.nix                     — Root flake (inputs, packages, devShell, nixosModules, checks)
flake.lock                    — (auto-generated by nix flake lock)
.envrc                        — direnv integration
dev/process-compose.yaml      — Local dev services (postgres, redis, awid, aweb)
nix/modules/default.nix       — NixOS module entrypoint (imports aweb.nix)
nix/modules/aweb.nix          — NixOS module for aweb + awid services
nix/tests/default.nix         — NixOS VM integration test (services start + health check)
```

```yaml
version: "0.5"

log_location: .data/dev.log

processes:
  postgres:
    command: |
      PGDATA="$(pwd)/.data/pg"
      if [ ! -d "$PGDATA" ]; then
        echo "Initializing PostgreSQL data directory..."
        initdb -D "$PGDATA" --auth=trust --no-locale --encoding=UTF8
        echo "port = 5433" >> "$PGDATA/postgresql.conf"
        echo "unix_socket_directories = '$(pwd)/.data'" >> "$PGDATA/postgresql.conf"
        echo "listen_addresses = '127.0.0.1'" >> "$PGDATA/postgresql.conf"
      fi
      exec postgres -D "$PGDATA"
    readiness_probe:
      exec:
        command: pg_isready -h 127.0.0.1 -p 5433
      initial_delay_seconds: 2
      period_seconds: 2
    shutdown:
      signal: 2
      timeout_seconds: 10

  redis:
    command: |
      mkdir -p .data/redis
      exec redis-server --port 6380 --dir .data/redis --daemonize no
    readiness_probe:
      exec:
        command: redis-cli -p 6380 ping
      initial_delay_seconds: 1
      period_seconds: 2
    shutdown:
      signal: 15
      timeout_seconds: 5

  db-init:
    command: |
      until pg_isready -h 127.0.0.1 -p 5433; do sleep 0.5; done

      # Create user and database if needed
      psql -h 127.0.0.1 -p 5433 -U $(whoami) -tc "SELECT 1 FROM pg_roles WHERE rolname='aweb'" postgres \
        | grep -q 1 \
        || psql -h 127.0.0.1 -p 5433 -U $(whoami) -c "CREATE USER aweb WITH PASSWORD 'aweb';" postgres

      psql -h 127.0.0.1 -p 5433 -U $(whoami) -tc "SELECT 1 FROM pg_database WHERE datname='aweb'" postgres \
        | grep -q 1 \
        || psql -h 127.0.0.1 -p 5433 -U $(whoami) -c "CREATE DATABASE aweb OWNER aweb;" postgres

      # Create awid schema
      psql -h 127.0.0.1 -p 5433 -U aweb -d aweb -c "CREATE SCHEMA IF NOT EXISTS awid;"

      echo "Database ready."
    depends_on:
      postgres:
        condition: process_healthy
    availability:
      restart: "no"

  awid:
    command: |
      cd awid
      exec uv run uvicorn awid_service.main:app --host 127.0.0.1 --port 8010 --reload
    depends_on:
      db-init:
        condition: process_completed_successfully
      redis:
        condition: process_healthy
    environment:
      - "AWID_DATABASE_URL=postgresql://aweb:aweb@127.0.0.1:5433/aweb"
      - "AWID_REDIS_URL=redis://127.0.0.1:6380/0"
      - "AWID_HOST=127.0.0.1"
      - "AWID_PORT=8010"
      - "AWID_DB_SCHEMA=awid"
      - "AWID_RATE_LIMIT_DISABLED=true"
    readiness_probe:
      http_get:
        host: 127.0.0.1
        port: 8010
        path: /health
      initial_delay_seconds: 3
      period_seconds: 5
    shutdown:
      signal: 15
      timeout_seconds: 10

  aweb:
    command: |
      cd server
      exec uv run uvicorn aweb.main:app --host 127.0.0.1 --port 8000 --reload
    depends_on:
      awid:
        condition: process_healthy
      redis:
        condition: process_healthy
    environment:
      - "AWEB_DATABASE_URL=postgresql://aweb:aweb@127.0.0.1:5433/aweb"
      - "AWEB_REDIS_URL=redis://127.0.0.1:6380/0"
      - "AWEB_HOST=127.0.0.1"
      - "AWEB_PORT=8000"
      - "AWID_REGISTRY_URL=http://127.0.0.1:8010"
      - "APP_ENV=development"
    readiness_probe:
      http_get:
        host: 127.0.0.1
        port: 8000
        path: /health
      initial_delay_seconds: 5
      period_seconds: 5
    shutdown:
      signal: 15
      timeout_seconds: 10
```

## Notes

- **vendorHash / npmDepsHash**: These must be determined empirically by attempting a build and reading the "got:" hash from the error. The plan marks these as TODO — Task 2 Steps 5-6 handle this.
- **Python packages**: The Nix derivations for aweb/awid are lightweight wrappers. Full dependency resolution for development uses `uv` directly (matching current workflow). The Nix packages serve the NixOS module for deployment.
- **Port choices**: postgres on 5433 (not 5432) and redis on 6380 (not 6379) to avoid conflicts with system services, following the scape pattern.
- **process-compose TUI port**: 9900 (via devrun command), following scape's pattern.
